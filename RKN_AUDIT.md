# Аудит OBHOD и RKN-Guard v3.0.0

Дата: 19 ноября 2026. Сравнение с повторно полученным https://github.com/Flecksis/rkn-guard, tag v3.0.0, commit 13cf9ef35212af3ffac9724c3250f6e9d7ea9a50. Сохранены незакоммиченные изменения проекта; firewall хоста и пользовательские серверы не изменялись.

## Что исправлено

- Совместимость протокола удалённого агента Anti-DDoS с транспортом бота: поля proto/result и отправка stdin. До исправления вызовы защиты и синхронизация списков через штатный транспорт могли не работать.
- При ошибке части источников предыдущий общий список объединяется с полученным, а не заменяется неполным набором; в ручной синхронизации отображается предупреждение. Пустой или невалидный источник считается ошибкой. Это консервативный общий кэш, не кэш каждого источника из upstream.
- Перезагрузка правил выполняется одной транзакцией nft с удалением и созданием таблицы; отказ команды не удаляет старую живую таблицу. Установка сообщает ошибку включения systemd; установщик проверяет ответ агента вместо безусловного заявления об успехе.
- Правила перенесены после conntrack (priority -10 вместо raw), чтобы проверка состояния соединения действительно имела смысл. FreeTurn больше не вставляет правило accept перед блокировками OBHOD; исключение порта в новом наборе находится после блокирующих правил.
- Выключенная защита не включается автоматически при следующем запуске бота; статус РКН не считается включённым при отсутствующей таблице. Число сетей подписано как данные кэша, а не live-измерение. Переключатель не сохраняет новое состояние в боте до успешного применения установленной защиты.
- Tools > Anti-DDoS > «Логи службы» показывает ограниченный журнал systemd с обновлением. Это журнал службы, а не события блокировки отдельных пакетов. Счётчики и список текущих блокировок уже доступны на экранах защиты.

## Важные отличия от upstream и незавершённые требования

OBHOD использует собственную реализацию nftables, а не бинарник rkn-guard и не является полной интеграцией v3. Требование пользователя о *всех* инструментах v3 не выполнено:

| Возможность v3 | Состояние в OBHOD |
|---|---|
| nftables и восстановление systemd | Собственная реализация; применена атомарная транзакция, требуется проверка на целевом сервере |
| iptables/ipset и выбор firewall/firewalld | Нет эквивалентного выбора backend; сосуществование с конкретной конфигурацией firewalld/UFW не проверено |
| Просмотр live-событий IPv4/IPv6, топ атак и накопительная статистика | Нет; добавленный экран показывает только журнал службы, а счётчики nft не заменяют live-журнал |
| Источники и last-good кэш каждого URL | Есть загрузка источников и консервативное сохранение общего предыдущего набора при частичной ошибке; независимого кэша, управления каждым штатным источником и полной диагностики нет |
| Обновление без сброса счётчиков | Нет: пересоздание таблицы сбрасывает счётчики и временные динамические наборы |
| Исключения IP + протокол + порт | Только общие исключения IP/CIDR; точных исключений по протоколу и порту как в v3 нет |
| Ручные блокировки IP | Имеются общие списки ручных банов |
| Автообновление независимо от бота | Нет: обновление периодически запускается работающим ботом; при недоступности источников используется ранее сохранённый набор или встроенный seed |

При частичной ошибке объединённый кэш может удерживать устаревшие сети до полностью успешного обновления. Числа в уведомлении о частичной загрузке относятся к полученным сетям, а не итоговому активному набору. Текущие активные соединения из блокируемых сетей пропускаются по established/related, в отличие от upstream. Исключения адресов и фильтры источников могут приводить к отличиям покрытия. FreeTurn-исключение после фильтров адресов и динамических блокировок по-прежнему обходит лимиты скорости на его порту. Ранее вставленные сторонним кодом правила могут сохраняться до пересоздания таблицы.

## Проверки и ограничения

- Полный pytest: 2669 тестов собраны, прогон успешен.
- watchdog policy/seal/verify, pyflakes, i18n audit (3 языка, 1447 ключей, 0 ошибок), git diff --check, bash -n: успешно.
- Реальный nftables v1.1.3 в изолированном user/network namespace: создан набор правил; UDP-пакет с тестового адреса через veth увеличил счётчик RKN drop до 1; заведомо невалидная транзакция не удалила существующую таблицу. Это не проверка всего трафика и не нагрузочный тест.
- Настоящий транспорт бота вызвал агент status и корректно обработал ответ. Синхронизация и ошибки проверены автоматизированными тестами.
- Производственный сервер, рестарт настоящей системы, SSH-сеанс администратора, все сочетания firewall, IPv6-трафик, реальные наводнения и Telegram UI на устройстве не проверены. При обновлении firewall возможен обрыв доступа. Перед использованием требуется консоль провайдера и испытание на отдельной тестовой машине.
- Дефолтное включение зависит от прав root, работающих nftables и systemd и доступности источников. Нельзя гарантировать защиту «из коробки» во всех окружениях и нельзя считать набор IP исчерпывающей защитой от сканирования или DDoS.
